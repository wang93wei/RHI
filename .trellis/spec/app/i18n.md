# i18n Guidelines

> JSON + ILocalizationService live-switching for WinUI 3. Covers resource layout, key naming, XAML/C# usage, fallback, and CI.

---

## Scope / Trigger
- Trigger: Any user-visible text (XAML, ContentDialog, ViewModel status) is added or changed. New language or key requires code-spec depth because it touches XAML binding, service fallback, persistence, and packaging.

## Signatures
- Service: `ILocalizationService` (`Services/ILocalizationService.cs:8`) — `CurrentLanguage {get;set}`, `FallbackLanguage`, `SupportedLanguages`, `GetString(key, args)`, `this[key]`, `ResolveSystemLanguage()`, `ApplyPreference(pref)`, `Coverage(lang)`, `LanguageChanged` event.
- Impl: `LocalizationService : ObservableObject, ILocalizationService` (`Services/LocalizationService.cs:12`) — singleton, `AddSingleton<ILocalizationService, LocalizationService>()` in `App.xaml.cs:92`.
- Persistence: `SettingsViewModel.Language` (`ViewModels/SettingsViewModel.cs:84`) — `[ObservableProperty] string _language = "System"`, `LoadSettingsFromDict/SaveSettingsToDict` key `Language`.
- XAML: `{Binding [Key], Source={StaticResource Loc}}` with `App.xaml` resource `<services:LocalizationService x:Key="Loc" />` (design-time) replaced at runtime via `App.xaml.cs:129 Current.Resources["Loc"]=loc`.
- Converter: `LocConverter` (`Converters/LocConverter.cs:8`) for `ConverterParameter` fallback.

## Contracts
- **Resource files**: `RenoDXCommander/Assets/Languages/{lang}.json` flat `key -> value`, `en-US.json` authoritative (1170 keys), `zh-CN/zh-TW/ja-JP/ko-KR` must match 1:1 (100% present; ~118 untranslated brand/URL/license/format-only, R3.4).
- **Key naming**: `Area.Component.Key` + `.Tooltip`/`.Placeholder`/`.Button` suffix, e.g. `Settings.Language.Title`, `Dialog.UnknownDxgi.Title`, `Stats.Shown` with `{0}` placeholder.
- **Fallback**: `CurrentLanguage -> en-US -> key` never throws; missing key logged once via `CrashReporter.Log("[Localization] Missing key")`.
- **System mapping**: `ResolveSystemLanguage()` exact -> alias (`en-GB->en-US`, `zh-Hans->zh-CN`) -> prefix (`zh->zh-CN`, `en->en-US`, `ja->ja-JP`, `ko->ko-KR`) -> `en-US`.
- **Persistence**: `settings.json` key `Language` values `System|en-US|zh-CN|zh-TW|ja-JP|ko-KR`, default `System`, old installs without key -> `System`.

## Validation & Error Matrix
| Condition | Error / Handling |
|-----------|------------------|
| Missing key in current & fallback | Return `key` + `CrashReporter.Log` once |
| `string.Format` FormatException | Log + return template |
| Single language JSON corrupted | `try/catch` + empty dict + Log, app still starts (fallback to en-US) |
| Unsupported `CurrentLanguage` set | Log + fallback to `en-US` |
| `settings.json` missing Language | Treated as `System` |
| Placeholder {0} count mismatch | Log + return template |

## Good / Base / Bad Cases
- **Good**: `Loc.GetString("Dialog.CachePurged.Content", count, size)` with `{0} {1}` in JSON, XAML `Text="{Binding [Settings.Title], Source={StaticResource Loc}}"`.
- **Base**: `Loc.GetString("Missing.Key")` returns `"Missing.Key"` and logs once.
- **Bad**: Hard-coded `Title = "Unknown dxgi.dll"` or `Text="Settings"` without binding; `new HttpClient()` in service; `async void` without `try/catch`.

## Wrong vs Correct
#### Wrong
```csharp
// XAML hard-coded, not live
<TextBlock Text="Settings" />
// C# hard-coded dialog
new ContentDialog { Title = "Unknown dxgi.dll Detected", Content = $"File {path}" }
// Missing using, duplicate ApplyPreference
ViewModel.Settings.Language = tag; loc.ApplyPreference(tag); // double event
```

#### Correct
```csharp
// XAML live binding via Loc resource
<TextBlock Text="{Binding [Settings.Title], Source={StaticResource Loc}}" />
// C# via service with placeholder
Title = Loc.GetString("Dialog.UnknownDxgi.Title");
Content = Loc.GetString("Dialog.UnknownDxgi.Content", path, sizeKB);
// SettingsViewModel.OnLanguageChanged single ApplyPreference
partial void OnLanguageChanged(string v) { App.Services.GetService<ILocalizationService>()?.ApplyPreference(v); }
// Service fallback never throws
return string.Format(CultureInfo.InvariantCulture, template, args); // try/catch
```

## Design Decisions
- **JSON over .resw**: Packaged as `Content` with `CopyToOutputDirectory`, no PRI generation, macOS buildable, live `OnPropertyChanged("")` for 200ms refresh, `x:Bind` not used for translatable text. See `design.md` Trade-offs.
- **StaticResource Loc + runtime override**: Design-time `<services:LocalizationService x:Key="Loc" />` satisfies XAML compiler, runtime `Current.Resources["Loc"]=locSingleton` ensures single source of truth before `MainWindow` loads.

## Common Mistakes
- Forgetting `using Microsoft.Extensions.DependencyInjection` for `GetRequiredService` in `DetailPanelBuilder.cs` -> CS1061.
- Adding `LocalizationService` property to every partial of `DetailPanelBuilder` -> duplicate definition; define once in `DetailPanelBuilder.cs` and share via partial.
- Using `{Binding [Key], Source={StaticResource Loc}}` without `App.xaml` dummy resource -> XAML compiler MSB3073.
